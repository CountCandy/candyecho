                🎙 What makes a good sample for Echo
                

                  

                    

                        
Length5–15 seconds is the sweet spot. Echo accepts up to about five minutes, but its author says clips of ten seconds or less already work well, and people who run it report that long clips rarely sound better. Short samples are what this model wants.

                        
How manyOne clip per voice. Echo cannot combine clips, and it needs no transcript.

                        
ToneConsistent, and already in the delivery you want. Echo has no emotion tags, so the clip's mood, pace and energy carry into everything it reads. A clip that swings from calm to shouting gives unpredictable results. For a second mood, save a second voice.

                        
RecordingOne speaker, no music, little room echo, no clipping. Background noise is cloned along with the voice.

                        
If it driftsRaise Force speaker in the advanced controls a little at a time. It is the fix for "that does not sound like the clip".

                    

                  

                  

                    

                        
Length10–30 seconds per clip. That is Fish Audio's own range; CandyEcho sends the first 30 seconds of each clip. Clips under ten seconds are below it, which is the likeliest reason short samples clone less closely here than in Echo.

                        
How manyTwo or three clips is Fish's recommendation, ideally 15–20 seconds each. With short samples, adding more of them under Extra reference clips is how you reach that total. Use 🎧 Audition to check that each one helps.

                        
ToneSteady inside each clip; variety, if you want it, across clips. Fish's guides disagree: one lists consistent tone and emotion as a must-have, another asks for varied intonation, a third says several samples capture more range. Read together: keep any single clip in one mood and volume, and use separate clips to cover different moods. A neutral, natural clip is fine, because direction tags supply the emotion later.

                        
TranscriptMust match the audio word for word. The model learns the voice by pairing each clip with its text, so a wrong word costs more here than anywhere else. Check the automatic transcript for names and unusual words, and prefer clips that start and end on a whole sentence.

                        
RecordingOne speaker, steady volume, no music or room echo, and short natural pauses (about half a second) between sentences. Quiet clips are brought up to a normal level automatically.

                ⚙️ Advanced generation controls
                

                    

                        
                        
                    
Fewer — faster and less VRAM. More — better odds one take is clean. All takes share a single pass, so this costs memory far more than time.

                    
Fewer — faster. More — better odds one take is clean. With this engine every take is a separate request, so three takes take three times as long.

                        
                    
Fewer — steadier pace. More — a bad chunk gets extra attempts. Only fires when a chunk still scores poorly, so most chunks never use it.

                        
                        
Checking verification models…

                        
The winning take also seeds the next chunk, so a caught error doesn't carry forward. Lets you raise expressiveness without losing words.

                    


                    

                    
                    
Fewer — faster, with rougher artefacts. More — smoother, and linearly slower: 80 steps really is twice the wait. Upstream recommends 40 and gains above it are small.

                    
                    
Lower — looser and more natural, but misreads and skips more words. Higher — crisper articulation that sticks to the text; too high sounds clipped and over-enunciated. Upstream uses 3.0.

                    
                    
Lower — freer delivery that may wander from your reference voice. Higher — hugs the reference; too high goes strained and artefacty. Upstream uses 8.0, so this is already firm.

                    
                    
Below 1.0 — steadier and safer, but flatter and more monotone. Above 1.0 — livelier and more varied, and drops or invents more words. Not a temperature: Echo's solver is deterministic, so this scales the starting noise. This is the dial Best-of-N lets you push.

                    
                    
Off (1.0) — no forcing, the normal case. Higher — drags a drifting voice back toward the reference, at the cost of flattening delivery. Upstream: use the lowest value that produces the right speaker; 1.1 or 1.3 is often enough.

                    


                    

                        
                        
Lower — steadier and more predictable. Higher — more varied, livelier takes that go wrong more often. Fish's default is 0.7.

                        
                        
Lower — keeps to the safest choices. Higher — allows rarer ones, for more colour and more risk. Fish's default is 0.7.

                        
                        
Lower — only the few likeliest sounds are considered: stable, flatter. Higher — a wider pool, livelier and riskier. Fish's default is 30.

                    


                    
                    

                    
Blank — a fresh flavour each run. Fixed — reproduces a run exactly, as long as the take count matches too (a batch of 3 draws different noise than a batch of 1).

            🎭 Directing delivery
            

              

                
Echo has no emotion tags. Writing (happy) or (sad) does nothing — at best it is ignored, at worst the word is read aloud. Tag vocabularies like that exist in ElevenLabs, Fish Audio and Qwen3-TTS, but Echo was never trained on one. Everything below is what it does respond to.


                
Punctuation — the reliable lever

                
These come straight from Echo's own documentation.

                

                    
You writeWhat happens

                    
,A pause. This is the main way to control rhythm.

                    
!More expressive delivery — upstream notes that punchier punctuation "may lead to increased expressiveness but also potentially lower quality on occasion".

                    
?Question intonation.

                    
… / ...A longer trailing pause.

                    
: ; —Silently converted to commas before the model sees them, so they all read as plain pauses.

                    
[S1] [S2]Speaker labels. [S1] is added automatically when absent; a second label switches speaker mid-text.

                


                
Non-speech events

                
Echo was trained on WhisperD transcripts, which annotate audible events in parentheses. These are sounds, not moods — there is no (happy) because nobody can transcribe a mood.

                
She read the last line. (sighs) It had all been for nothing.

                
Documented upstream: (laughs) · (coughs) · (sighs)

                
Recognized but untested — same family, no guarantee Echo learned them: (chuckles) (giggles) (gasps) (clears throat) (whispers) (groans) (grunts) (yawns) (scoffs) (snorts) (sniffs) (sobs) (exhales) (inhales)

                
Any of these keep their parentheses through normalization, so Echo sees them as events. Ordinary parenthetical prose like (see chapter four) is still flattened to commas and spoken.

                
Test one before trusting it. Generate a line with the tag and listen: if you hear the word "yawns" spoken, that tag is not in the model's vocabulary. With Best-of-N on, this also shows up as a word-error spike on that chunk.


                
What actually carries emotion

                
    
                    
  1. The reference clip. By far the biggest lever. Echo attends over your whole sample, so its pacing and emotional register carry into the output. A clip of animated, warm delivery produces animated, warm delivery; a flat one produces flat.
    2. 
                    
  2. The Expressiveness slider in advanced controls. It widens variety rather than choosing a feeling, and costs accuracy as it climbs.
    3. 
                    
  3. Punctuation, per the table above.
    4. 
                

              


              

                
Drama 3 is directed inside the script. Write the direction the way you would say it to an actor. The ✨ Add direction tags button under the text box can write a first pass for you.

                

                    
You writeWhat happens

                    
[warm, unhurried]A line direction, in plain words. It applies to everything after it until the next direction.

                    
[sigh] [laugh] [breath] [pause]A sound or a beat at exactly that point.

                    
<whisper>come alone</whisper>A paired tag changes only the words inside it.

                

                
Paired tags: <whisper> <emphasis> <soft> <fast> <slow> <stress> <forceful>

                
[barely holding it together, forcing a smile] I'm fine. [shaky breath] Really. Go on <soft>without me</soft>.

                
Long text is sent a chunk at a time. CandyEcho repeats the direction still in force at the start of each chunk and closes and reopens any paired tag that spans a chunk edge, so your markup behaves as if the script were sent whole. Results still vary between takes: change the seed, or turn on Best-of-N.

            🔌 Use CandyEcho as a TTS backend (SillyTavern & other apps)
            

                
CandyEcho exposes an OpenAI-compatible speech endpoint, so anything that speaks the OpenAI TTS API can use it as a backend.

                
Base URL http://localhost:8100 · Endpoint POST /v1/audio/speech


                
SillyTavern

                
    
                    
  1. Open Extensions → TTS and set TTS Provider to OpenAI Compatible (click Reload if the fields don't appear).
    2. 
                    
  2. Provider Endpoint: http://localhost:8100/v1/audio/speech
    3. 
                    
  3. Model: candyecho  ·  API Key: not-needed
    4. 
                    
  4. Available Voices: enter your voice names from the list above (comma-separated), then map characters to them.
    5. 
                


                
Raw API

                
curl -X POST http://localhost:8100/v1/audio/speech \
  -H "Content-Type: application/json" \
  -d "{\"input\":\"Hello from CandyEcho!\",\"voice\":\"YOUR_VOICE\",\"response_format\":\"wav\"}" \
  --output out.wav

                
response_format: wav (default), mp3, flac, ogg. List voices at GET /v1/audio/voices. model picks the engine: candyecho (Echo) or drama3, which must be downloaded first and is started on demand. speed is accepted for compatibility but ignored.

                
Running SillyTavern on another machine? Start CandyEcho with --host 0.0.0.0 and use this PC's LAN IP in the URL instead of localhost.
